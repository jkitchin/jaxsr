# JAXSR browser app

A zero-install front end for JAXSR, published at
<https://kitchingroup.cheme.cmu.edu/jaxsr/app/>. Upload a spreadsheet, pick which
columns are features and which is the target, choose which families of functions the
search may draw from, and get a ranked table of candidate equations with diagnostics
and exports.

Everything runs in the visitor's browser through WebAssembly. No data is uploaded,
and there is no server to operate.

## How it runs without JAX

`jaxlib` is a compiled XLA wheel with no Emscripten build, so JAX cannot run under
Pyodide. JAXSR barely needs it: across `src/jaxsr` there are ~1300 `jnp.*` calls, all
of which name functions NumPy also has, plus a short tail of genuinely JAX-specific
API (`jax.jit`, `jax.grad`, `jax.lax.erf`, `.at[]` index updates, `jax.random`).

`py/jax_shim.py` supplies that tail on top of NumPy and registers itself in
`sys.modules` before `import jaxsr`, so the library itself needs no changes. The
substitution is only trustworthy if JAXSR behaves the same on top of it, so the whole
test suite runs against the shim in CI:

```bash
python scripts/test_under_numpy.py            # the full suite, on NumPy
pytest tests/test_numpy_shim.py               # shim contract + agreement with real JAX
```

Two differences are deliberate. NumPy defaults to float64 where JAX defaults to
float32, which puts `selection.py` on its closed-form MSE path and makes the
finite-difference steps in `constraints.py` more accurate. And NumPy's linalg raises
where JAX returns NaN, so `py/jax_shim.py` wraps `jnp.linalg` to return NaN — without
that, the `solve` → `isfinite` → `lstsq` fallback in `selection.py:290` never runs.

## Layout

| Path | What it is |
| --- | --- |
| `index.html` | the page |
| `css/app.css` | styles, light and dark |
| `js/main.js` | UI state machine; owns the DOM |
| `js/worker.js` | boots Pyodide and owns every Python call |
| `js/dataio.js` | spreadsheet parsing and the column-role table |
| `js/plots.js` | inline-SVG charts |
| `js/report.js` | ranked table and detail pane |
| `py/jax_shim.py` | NumPy stand-in for JAX |
| `py/kernel.py` | the app's Python API: JSON in, JSON out |
| `vendor/` | SheetJS (Apache-2.0), vendored and pinned |
| `wheels/`, `manifest.json` | generated by `scripts/build_webapp.py`; gitignored |

Python runs in a Web Worker so a long fit never freezes the page, and every kernel
function returns a JSON string, so no `PyProxy` objects cross into JavaScript.

Spreadsheets are parsed in JavaScript rather than Python. That works the instant the
file is dropped — the user assigns column roles while Pyodide is still booting — and
it keeps pandas and openpyxl out of the download. Charts are hand-built SVG for the
same reason: matplotlib would add roughly 10 MB, and SVG inherits the page's theme
and saves as a real `.svg`. SymPy is fetched only when someone asks for LaTeX.

## Running it locally

```bash
python scripts/build_webapp.py                # build the wheel + manifest
python -m http.server -d webapp 8000
```

Then open <http://localhost:8000>. Opening `index.html` from the filesystem will not
work: the worker and the wheel are fetched over HTTP.

After changing `py/kernel.py` or `py/jax_shim.py`, just reload the page — those are
fetched at boot. After changing `src/jaxsr/`, re-run `scripts/build_webapp.py` to
rebuild the wheel.

## Deployment

`.github/workflows/docs.yml` builds the wheel and copies `webapp/` into
`docs/_build/html/app` before the GitHub Pages upload. The app deliberately lives
outside `docs/` so jupyter-book never tries to process it.

`js/worker.js` derives its asset root from its own URL, so the app works both at `/`
locally and under `/jaxsr/app/` when published.

## Pinned versions

`scripts/build_webapp.py` pins the Pyodide release. 0.29.3 ships CPython 3.13 with
NumPy 2.2 and SciPy 1.14, closest to what `scripts/test_under_numpy.py` validates
against; newer Pyodide runs CPython 3.14, outside the versions jaxsr's CI covers.
Before bumping it, check that numpy, scipy and sympy are all still in that release's
`pyodide-lock.json`.
